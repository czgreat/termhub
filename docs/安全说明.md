# 安全与运维边界

## 访问权限

termhub 是远程终端工具。把 CLI 配置绑定给用户，等于允许该用户访问节点安装账号有权访问的文件和执行程序；文件夹范围不是操作系统沙箱。只授权可信用户，按需使用独立 Windows 账号。Hub 使用密码和 TOTP，受信设备与恢复码也应妥善保管。

termhub 不修改官方 Claude Code/Codex，不管理它们的登录；历史读取不会写入、删除或移动官方文件。历史列表中隐藏项目只改变 termhub 元数据。

## 网络

默认 HTTPS 27443 只绑定局域网地址，不直接暴露到公网。初次接受自签证书前，比对浏览器证书 SHA256 与 Hub 的 cert_fingerprint；节点通过 --pin 校验相同证书。维护者需要自行限制防火墙来源。

外网入口应使用 HTTPS 反向代理或隧道。可选的明文监听由 TH_PROXY_LISTEN 开启，配置示例见 deploy/hub.env.example；它只能被反代访问。将允许的浏览器 https 来源列入 TH_PUBLIC_URL，TH_TRUSTED_PROXIES 仅填写真实代理地址，设置 TH_PROXY_KEY 并由代理发送 X-TH-Proxy-Key。不要把反代密钥提交仓库。配置前阅读 internal/hub/server 中的代理校验逻辑。

## 备份与回滚

备份整个 Hub data 目录，包含 SQLite 数据库、master.key 和 TLS 证书。停掉 Hub 后复制是最简单的一致性备份方式；停机期间节点持有的终端仍可运行。仅复制正在写入的单个 SQLite 文件不保证一致。

数据库迁移前会自动生成 pre-migrate-vN 备份。这不能替代定期离机备份。丢失 master.key 会使保存的密文无法解开。涉及迁移的回退需停止 Hub 后恢复匹配版本的完整备份，恢复点之后的数据会丢失。

agent 升级仅重启 run，已有 host 不会随本次脚本升级；需要升级 host 时，先主动结束全部会话，再安排节点重启。它们不因网页断线退出，但电脑重启会结束会话。节点升级前保留旧包，升级失败查看日志并恢复旧程序，不反复执行安装或重新登记。

## 报告问题

不要在 Issue、截图或日志附件中包含令牌、TOTP 密钥、恢复码、Cookie、真实对话、个人路径或未脱敏的网络配置。发布包暂未做代码签名；SHA256 用于核对下载完整性，不能代替对发布账号的信任。
