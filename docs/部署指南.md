# 部署指南

termhub 由三部分组成：

- **Hub**：跑在一台 Linux 主机上，用 Docker 运行。
- **agent**：每台要用的 Windows 电脑上各一个。
- **网页**：内嵌在 Hub 里。

下面按顺序操作。命令都在仓库根目录执行，Windows 上用 Git Bash 运行 `.sh` 脚本。

预编译包用户直接阅读 [发布包安装说明](发布包安装.md)，以下为源码构建方式。

## 0. 准备

| 机器 | 需要 |
|---|---|
| 构建机（任意系统，Windows 也行） | git、Go 1.27 或更高、Node.js 22.13.0 或更高（带 npm，建议使用 CI 同款 22.x）；要远程部署还需要 ssh/scp，并能免密登录 Docker 主机 |
| Docker 主机（Linux，NAS、小主机、虚拟机都行） | Docker 和 compose 插件；开启时间同步（TOTP 依赖准确的时钟） |
| 每台 Windows 电脑 | Windows 10 1809 或更高、Windows 11 或 Windows Server 2019 及以上；PowerShell 7（MSI 版）；要用的 CLI（Claude Code、Codex）已按官方方式装好并登录 |

- 构建机和 Docker 主机可以是同一台 Linux 机器：第 2 步用 `bash deploy/release.sh local`。
- 网络：浏览器和各台 Windows 都要能访问 Docker 主机的 27443 端口。

## 1. 获取代码

```bash
git clone https://github.com/czgreat/termhub.git termhub
cd termhub
```

部署命令统一用 `bash` 调用脚本，不依赖 Git 或快照导出是否保留可执行权限。网页单测使用 `stripTypeScriptTypes`，Node.js 20 不满足要求。

## 2. 部署 Hub

先运行一次发布脚本，它会在目标主机上生成两个配置文件，然后停下：

```bash
bash deploy/release.sh user@docker-host        # 远程：目录默认为 ~/termhub
# 或者在 Docker 主机本机上：
bash deploy/release.sh local
```

编辑目标主机上 `~/termhub` 里的两个文件：

- `.env`：`TH_BIND_ADDR` 填这台主机的局域网地址，例如 `192.168.1.10`。27443 端口只在这个地址上开放。
- `hub.env`：`TH_PUBLIC_URL` 填浏览器访问 Hub 的地址，例如 `https://192.168.1.10:27443`。有多个地址时用逗号隔开，只能是 https。

再运行一次同样的命令。脚本会做这些事：

1. 构建网页。
2. 交叉编译 Linux 版 Hub（网页内嵌在里面）和 Windows 版 agent（生成在 `dist/termhub-agent.exe`）。
3. 在目标主机上构建镜像。镜像只包含一个静态程序，不拉取任何基础镜像。
4. 启动容器，等健康检查通过。
5. 输出两行信息，记下来：
   - `setup_token`：一次性令牌，用来创建第一个管理员。
   - `cert_fingerprint`：Hub 证书的指纹，登记节点时用。

说明：

- 默认编译 amd64 版本。ARM 主机用 `TH_ARCH=arm64 bash deploy/release.sh ...`。
- 下载 Go 模块慢时，可以设 `GOPROXY`（例如 `https://goproxy.cn,direct`）。
- 数据都在 `~/termhub/data`，里面有数据库、主密钥和证书。请整个目录一起备份。
- 不想在构建机上装 Go 和 Node 时，也可以在能访问 Docker Hub 的主机上完全用 Docker 从源码构建（这条路没有 release.sh 那样实测过）：
  ```bash
  docker build -f deploy/Dockerfile --build-arg VERSION=0.1.0-local -t localhost/termhub:0.1.0-local .
  mkdir -p ~/termhub/data && cp deploy/docker-compose.yml ~/termhub/
  cp deploy/.env.example ~/termhub/.env && cp deploy/hub.env.example ~/termhub/hub.env   # 按上面填好
  printf 'TERMHUB_VERSION=0.1.0-local\nTERMHUB_UID=%s\nTERMHUB_GID=%s\n' "$(id -u)" "$(id -g)" >> ~/termhub/.env
  cd ~/termhub && docker compose up -d
  ```
  以 root 身份操作时，把 UID、GID 写成 65532，并执行 `chown -R 65532:65532 data`。agent 仍需用 Go 编译：`GOOS=windows GOARCH=amd64 go build -o termhub-agent.exe ./cmd/termhub-agent`。

## 3. 创建管理员

1. 浏览器打开 `TH_PUBLIC_URL`。证书是 Hub 自签的，浏览器第一次会提示不安全。可以在浏览器的证书详情里核对 SHA-256 指纹，和日志里的 `cert_fingerprint` 一致再继续。
2. 填入 `setup_token`，设置管理员的用户名和密码。
3. 用手机上的验证器（Google Authenticator、1Password 等）扫码绑定 TOTP。
4. 保存恢复码。

令牌不见了可以查日志：`docker logs termhub`。

## 4. 接入 Windows 电脑

在网页上打开“⚙ 管理 → 节点”，填一个名称，点“添加节点”。页面会显示一条登记命令，里面有 Hub 地址、令牌和指纹（`--pin`）。令牌只显示一次。

把 `dist/termhub-agent.exe` 和 `deploy/install-agent.ps1`、`deploy/upgrade-agent.ps1`、`deploy/uninstall-agent.ps1` 拷到那台 Windows 上，放在同一个文件夹里。然后以**要使用的那个 Windows 用户**身份，在普通（不提权）的 PowerShell 窗口里运行：

```powershell
.\install-agent.ps1 -Hub https://192.168.1.10:27443 -Pin <指纹>
```

脚本会提示你粘贴节点令牌。也可以用 `-Token thn_...` 直接给出，但那样令牌会留在 PowerShell 的命令历史里。

- 默认在这个用户登录 3 分钟后自动启动。
- 加 `-AtStartup` 则开机就启动，不需要有人登录。这时要用同一个用户“以管理员身份运行” PowerShell（Windows 只允许提权的窗口注册开机任务）。Windows 会要一次该用户的密码，密码由计划任务服务保存，termhub 不经手。本脚本的开机模式要求安装账号本身属于管理员组，并具有“作为批处理作业登录”权限；标准账号请先使用默认登录模式。不要通过输入另一个管理员账号来提权，否则会装到另一个用户目录。
- 同一台电脑上的第二个 Windows 用户也要装时，加 `-TaskName termhub-agent-<用户名>`；以后升级、卸载时传同样的 `-TaskName`。
- 运行 PowerShell 脚本被拒绝时，先执行：`Set-ExecutionPolicy -Scope Process Bypass`。

几秒钟后，节点在“管理 → 节点”里显示为“在线”。

## 5. 添加 CLI 配置并分配给用户

在“管理 → CLI 配置”里，用模板按钮（PowerShell、Claude Code、Codex）给节点添加配置。

- 可以设置默认工作目录。
- 在“绑定给用户”里勾选能用它的人。

**注意**：绑定就等于允许那个人通过网页访问这台电脑上、那个 Windows 用户能访问的全部文件。这不是安全隔离，只绑给你信任的人。

普通用户在“管理 → 用户”里创建。第一次登录时，用户要修改临时密码并绑定 TOTP。

## 6. 从外网访问（可选）

不要把 27443 直接开到公网。推荐的做法是用一个带 HTTPS 的反代（Caddy、Nginx 等）或隧道（FRP 等）转到 Hub 的明文反代监听：

1. 在 `hub.env` 里打开 `TH_PROXY_LISTEN=:27180`，并设置 `TH_TRUSTED_PROXIES` 为反代的地址。
2. 用隧道时再设置 `TH_PROXY_KEY`，并让反代带上 `X-TH-Proxy-Key` 请求头。
3. 把公网地址也加进 `TH_PUBLIC_URL`。
4. 反代跟 Hub 不在同一个 compose 网络时，在 `docker-compose.yml` 里把 27180 也发布出来，同样只绑一个地址。

反代需支持 WebSocket 升级，设置适合长连接的超时及上传大小限制，并正确传递转发头；信任边界见 [安全说明](安全说明.md)。

## 7. 升级

- **Hub**：`git pull` 后重新运行  `bash deploy/release.sh user@docker-host`（本机 Docker 用 `bash deploy/release.sh local`）。数据不动。有数据库迁移时，Hub 启动前会自动把数据库备份到 `data/backups/`。
- **agent**：把新的 `dist/termhub-agent.exe` 拷到那台电脑，以同一个用户身份运行：

  ```powershell
  .\upgrade-agent.ps1 -Exe .\termhub-agent.exe
  ```

  只重启 agent 进程，会话宿主不动，正在跑的会话不会断。

## 8. 卸载

- **Windows**：运行 `.\uninstall-agent.ps1`，然后在“管理 → 节点”里删除这个节点。卸载会结束这台电脑上的所有 termhub 会话；官方 CLI 和它们的历史记录不受影响。
- **Hub**：在 Docker 主机上执行 `cd ~/termhub && docker compose down`。`data/` 目录需要自己删除。

## 常见问题

| 现象 | 处理 |
|---|---|
| 浏览器登录时提示来源不对 | 浏览器地址栏里的地址（含端口）必须写在 `TH_PUBLIC_URL` 里 |
| 登记失败，提示指纹不符 | `--pin` 要用“管理 → 节点”页顶部显示的指纹 |
| 节点提示“pwsh 是商店版” | 卸掉 Microsoft Store 版的 PowerShell，改装 MSI 版 |
| 节点重启后不上线 | 默认需对应用户登录后等待 3 分钟；无人登录时请安装为 `-AtStartup`。 查看计划任务 `termhub-agent` 的状态和 `%LOCALAPPDATA%\termhub\agent\logs\agent.log`。用 `-AtStartup` 安装的，改过 Windows 密码后要在任务计划程序中更新该任务保存的密码，不要为此卸载重装 |
| 动态码总是不对 | 核对 Docker 主机和手机的时间 |
