# v0.1.0 发布包安装

从仓库 Releases 下载，不需要 Go 或 Node.js。节点只支持 Windows amd64；Linux amd64/arm64 是 Hub 包。ARM64 为交叉编译，未做 ARM 真机验收。所有包未签名，请从可信发布账号下载并核对 SHA256SUMS.txt。

## 核对下载

Linux 在包和 SHA256SUMS.txt 所在目录执行：
```sh
sha256sum --check --ignore-missing SHA256SUMS.txt
```

Windows PowerShell 7：
```powershell
Get-FileHash .\termhub_0.1.0_windows_amd64.zip -Algorithm SHA256
```
将结果与 SHA256SUMS.txt 对应文件那一行比较。校验和验证文件是否一致，不替代代码签名或下载来源认证。

## Linux Hub：首次安装

选与你的 Linux 主机架构一致的 tar.gz。每包包含程序、Dockerfile、compose、配置模板和镜像所需的 etc/data 文件，不需要拉取基础镜像。需要 Docker 与 compose 插件。

在新目录解压，以下以 amd64 为例：
```sh
mkdir termhub-0.1.0
tar -xzf termhub_0.1.0_linux_amd64.tar.gz -C termhub-0.1.0
cd termhub-0.1.0
cp .env.example .env
cp hub.env.example hub.env
chmod 600 .env hub.env
```
编辑 .env：TH_BIND_ADDR 填本机局域网地址，TERMHUB_VERSION 填 0.1.0；编辑 hub.env：TH_PUBLIC_URL 填浏览器访问的 HTTPS 地址。不要照搬示例地址。

容器运行账号必须能写入 data。普通账号使用自己的 uid/gid；以 root 操作则使用 65532：
```sh
uid=$(id -u); gid=$(id -g)
if [ "$uid" = 0 ]; then uid=65532; gid=65532; chown -R "$uid:$gid" data; fi
# 用文本编辑器将 .env 内 TERMHUB_UID / TERMHUB_GID 设置成上述 uid / gid。
printf 'Set TERMHUB_UID=%s and TERMHUB_GID=%s in .env\n' "$uid" "$gid"
docker build -t localhost/termhub:0.1.0 .
docker compose up -d
docker compose ps
docker logs termhub
```
等状态 healthy 后，在浏览器打开 TH_PUBLIC_URL。核对证书指纹，用日志中的 setup_token 创建管理员并绑定 TOTP。步骤详见部署指南第 3 节。

## Windows 节点

解压整个 Windows zip，包含 exe、install-agent.ps1、upgrade-agent.ps1、uninstall-agent.ps1。保持脚本与 exe 同目录，使用 PowerShell 7 MSI 版。

以准备运行 CLI 的 Windows 账号打开终端：
```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\install-agent.ps1 -Hub https://192.168.1.10:27443 -Pin <网页给出的证书指纹>
```
替换示例地址和指纹，按提示输入网页生成的节点令牌。官方 CLI 需用户自行安装和登录。

**默认是用户登录后延迟 3 分钟启动，不是开机启动。** 要无人登录也在线，安装账号本身须属于管理员组，以同一身份提权并加 -AtStartup，自己在凭据弹窗输入密码。改 Windows 密码后须更新任务保存的密码。标准账号用默认登录模式；不要换另一个管理员身份安装。

## 更新与回滚

- Hub：把新包解压到另一个构建目录，构建新版本镜像。在原部署目录备份整个 data 和 .env（停止 Hub 后复制以确保一致），更新 .env 的 TERMHUB_VERSION，再执行 docker compose up -d。不要把新包的空 data、配置模板覆盖到原目录。没有迁移可换回旧镜像；有迁移要恢复对应完整数据备份，会丢失恢复点后的数据。
- 节点：以原安装账号，在新解压目录运行 `./upgrade-agent.ps1 -Exe ./termhub-agent.exe`。使用自定义任务名时传相同 -TaskName。脚本先检查新程序，再备份旧文件，只重启 run；已有会话 host 保持原版本。
- 若节点新程序无法启动：保留旧 exe；查看日志。确认无新 run 在运行后，把安装目录内新 exe 移到独立备份名，将脚本输出的旧备份文件改回 termhub-agent.exe，再启动原计划任务。不要停止 host，不要重新 enroll。
- 卸载：uninstall-agent.ps1 会立即结束该用户的全部 termhub 会话并删除安装目录，不会逐个询问。执行前自行确认已保存工作；它不是更新密码或升级的步骤。

更多配置与信任边界见部署指南.md、安全说明.md。
